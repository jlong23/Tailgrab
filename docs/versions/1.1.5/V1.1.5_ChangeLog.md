## Configuration Changes

- Added new Action for Playing a local sound file when configured in the actions of a line handler.  This can be for something like 'Vote To Kicks' and get a sound to play to get your attention.  See the [Config Tab, Line Handlers PlaySoundAction](../../Config_LineHandlers.md#playsoundaction-definition-in-actions)
- Group GIST Processing:
	- New progress logging in the log file for every 50 records processed to give the user a better idea of how long it will take to process large GISTs.
	- Exposure of the Record Processing status in the Statusbar of the application to give the user a better idea of how long it will take to process large GISTs.
	- GIST file Alert Priority override - If the GIST record has a stronger alert level than the user has configured for that group, the GIST record will override the user configured alert level and use the GIST record's alert level. This should allow groups managing their alerts to control the higher level of 'Alertedness'
	- Light refactoring of the GIST processing code to make it easier to maintain and add new features in the future.
	- Check GIST button for Group now overides the Checksum check and will always check the GIST file for updates.  This is to allow users to force a recheck of the GIST file if they suspect it has been updated since the last time it was checked or detect deleted groups in the database (Were UpdatedDate < Now()/Cutton Click Time)
	- Check GIST button for Group now passes the URL of the GIST file Textbox to the processing code, this allows the primary load process as well as the ability to Merge in other GIST files from other sources; as so long as you don't save the page, the Prior URI will still remain in the Registry for next startup of Tailgrab.

## Behavioural Changes
- AI Evaluation / Ollama performance logging; I have seen some backlogs of the AI evalutation to take a long time to process, so I have added logging to the log file to see how long it takes to process each user.  This should help me identify if there is a performance issue with the AI evaluation and if so, what is causing it.  Most of the time we should see 4 second or less processing of user bios.
- Moderation Reports:
	- New Table to hold onto all the in game moderaton reports you have submitted to VRChat.  This will allow you to see what you have reported and when, as well as the ability to export the reports to a CSV file for your own records.
	- This table is updated on startup for any WEB Reporting you have submitted to VRChat, and will be updated when you submit a new report from the application.
	- When a user has been reported by you and they join, they will get a new Alert Message to let you know that you have reported this user before and put the contents into the user event panel.

	- Converted the User Trust to Icongraphy to make it easier to see the trust level of the user at a glance.
	- Added User Age verification Iconography to make it easier to see the age verification of the user at a glance.
	- Change Alert Message column to set Icongraphy of the Alert Level grouping, then Sectional Grouping of alerts.  This should make it easier to see the highest priority alert for a user at a glance.
	- Change the User Bio text to add the User Trust and Age Verification as text:  This does make the AI evaluation to be re-tested, so it's unfortunaly going to be a bit of a wait for user sets/bios to be re-cached.
	- Changed the priority of the AI Evaluation to users that have been evaluated before to speed the load of a heavy instance.

	- Added new Icongraphy for the evaluation state of the user supplied images, this should make it easier to see the evaluation state of the user supplied images at a glance.
	- Added the actual evaluation text to the grid to make it easier to make a decision on reporting the user supplied images at a glance.
	- Changed the 'Smoothness' of the scroll area for each of these pages to allow mouse wheel scrolling to be more responsive and less jumpy.
- Ban Management Page:
	- Added a new button to report user 'In Game' since VRC only likes the ingame reporting of users, letting you type in more details about the user; I am writing nice articles about crasher uploaders and suspected alt accounts with this now.
